本轮性能依据：`HCurveObject.continueStroke` 累积曲线并单独维护当前线段；`HBezierObject.drawLine` 向路径添加逆时针椭圆。Fcboard 此前每帧将全部钢笔几何序列化成 SVG 后交给 Path2D 解析，并在采样 RAF 后再次排队渲染。现在 `factoryPath.ts` 直接构造原生 Path2D、只追加稳定的曲线 / 椭圆，临时触点尾段不进入累积缓存；`NewElementCanvas` 用 layout effect 直接提交该帧。保留完整合并采样；样本修改、擦除及样式变化会校验并重建缓存。Canvas / SVG 共享 trace，已有几何与增量操作回归；尚无真机帧耗时数据，不能声称卡顿已全部消除。

多指补充：原 `centerPointBetweenArea` 的 `area` 实为第一个触点到其余触点的距离总和，中心为最后一次迭代得到的首末触点中点；不是多边形面积。主画板按此度量保留 0.5..2 的增量缩放，增加 / 松开触点只更新基线、不改变视图。单点 / 多点书写继续沿独立采样分支，不把第三处笔迹变成缩放。浏览器保留 CSS 浮点坐标，变换继续共用现有 getStateForPinch 的连续锚点映射；未逐字复制 Android Point 的整数截断与同向移动门控，物理同时采样差异仍需同机对照。

课件补充：共享 `inkRecognition.ts`，保留原始采样及压力，文字原位替换、算式右侧补结果、函数本地生成可调图；更改笔型、删除、换页或失焦取消在途结果。资源异步载入增加可见课件身份 / 页码检查；原笔迹替换与插入同次撤销。相关触及 `FilePreview`、`documentInk`、`documents`、`TeachingResources`。MUI 组合依据为 [官方 MenuList + Popper](https://mui.com/material-ui/react-menu/#composition-with-menu-list)；没有引入 Card。

本轮收笔依据：`HBezierObject.onUp` 明确将最后一个节点的宽度设为 0；主板单 / 多点和课件提交同一 `finished` 标记，Canvas / SVG 及擦除几何一起读取，旧笔迹不追溯改变。擦除片段保存完整宽度（包括 0），不把新裁剪端点当抬笔重新收尖；连续椭圆宽度参与裁剪，避免逐段最大宽度在收笔处留下碎屑。课件从触点变大 / 笔键进入擦除、原厂橡皮预览、取消回滚及单次撤销有交互回归。普通笔 `HCurveObject.addNib` 的独立填充尾锋仍未实现。

目录迁移补充：保留用户的 `app` / `app/fcboard` / `packages/fcboard` 迁移及现有包别名，修复剩余 8 处失效的相对导入，移除锁文件迁移产生的重复 `packages/fcboard` importer（保留包含当前 MUI 依赖的条目）。按用户新项目要求，只保留 fcboard 数据键，移除重复回退；修复保存设置后误删同一新键，保留会话密钥 / 显式记住密钥语义。用户进一步要求先推送构建以便实测，允许在整体目标未完成时提交本轮验证版本；CI / 真机结果必须单独记录。

圈选 AI：移除计算 / 图像 / 问答三个按钮，唯一 AI 先识别，再依据校验后的表达式分流到本地数学，其他内容进入问答 / 原命令路由；明确讲解请求调用现有 lesson.ask。函数无效时不转图像生成，手写识别失败不另走一次视觉猜答；原搜索仍先识字再打开内部网页。讲课参考继续核对 `ss/whiteboard-teacher-main/docs/SCRIPT_API.md` 的分步脚本 / 同步板书语音、`ss/teach-learn-whiteboard-main/src/ai/prompt.ts` 的增量写板与来源约束，及 `ss/ai-math-tutor-main/apps/agent/src/canvas_protocol.ts` 的有界动作数据。未移植独立聊天页面或任意脚本。

原厂识别依据：`ModelManager.java`、`RecognitionModelBootstrapper.java`、`HSlide.createSmaText`、Digital Ink `zzfx / zzwa / zzwe` 与 model.zip / properties。`assets/model.tflite` 的 224×224 输入由 `HCanvas.drawSmaPicture` 使用，是图示分类；`hw.ttf` 属四线格字母对象。SDK / 模型移植文件为 `DigitalInkModels.java`、`DigitalInkPlugin.java`、`scripts/ink-models.json`；没有复制厂商安装身份或执行任意原生脚本。

目标是保持出厂白板的书写、擦除和触控体验，再将 AI 接入原操作。当前没有真机量化验收结果，不能把本记录或单元测试当作“90% 还原”认证。

## 本轮实测问题与依据

- 设置：`AboutPopu.java` 使用全屏遮罩，`layout_about.xml` 中内容居中，宽 373dp、34dp 设置行、13sp 标签；原 APK 并非左侧导航。按用户本轮明确要求，将 Fcboard 设置扩为居中横向 MUI Dialog，常驻左侧分类、右侧紧凑设置行；宽上限 960px、高上限 600px，小屏保留分类和独立滚动。背景、画笔、触控、模型、识别、语音、教学与原导出 / 协作共用窗口；“更多 → 设置”直接打开。依据安装的 MUI 9.5.0 类型及[官方 Dialog 文档](https://mui.com/material-ui/react-dialog/)，不使用卡片。新增实际打开设置、画笔和表格的 390 / 800 / 1280 / 1920 / 3080 / 3840 页面检查，不能拿关闭菜单的截图替代验收。
- 浮层实测：8973cfa 的 40 项页面测试有 35 项通过，新增的 5 项桌面表格位置检查复现左上角错误；`ToolButton` 只传 data-testid，丢失 data-board-insert，导致定位钩子找不到入口。现补全部 data 属性透传，并在入口不存在时居中，fixed 浮层使用视口坐标；原锚点、边界检查保留，待下一次 CI 复核。8 项 Android 真实模型仪器测试独立通过。
- 函数：`Classroom.createPlot` 原先偏向下方加 245，`FilePreview` 偏向右侧加 240；现将源区域传给 `fitPlot`，以源中心搜索四周可见空位，源区域整体列为障碍，无空间则统一缩小或保留原笔迹。继续由本地表达式生成轴和曲线。

- 四线格：插入后清除对象选择并切到可见板书的画笔，避免刚插入就弹属性或只能拖动；手动选择对象仍可编辑。原厂字母自动吸附 / `hw.ttf` 的完整交互尚待补齐。

## 用户指定的 CircleToSearch 区域交互

圈选确定算式、函数沿原数学链路执行；明确问题 / 操作请求复用现有命令路由。问答和总结写入真正可编辑的白板文本，课件打开时路由到当前批注层；讲解沿现有逐步绘图控制器。普通标题不自动改写，选区变化使过期回答失效。模型只能执行已注册命令，不能据此声称所有原版能力已实现。

AI 仍需真实模型 ID、密钥与可访问的兼容接口。修复取消信号覆盖超时、原生请求取消等待、非 JSON 网关错误；设置中可测试未保存配置，有白板内容时同时发送视觉上下文。按用户的新项目要求保留当前 fcboard 配置及会话密钥语义，不再额外回退旧 fcdraw 数据键。更换 Android applicationId 会建立独立应用沙箱，不属于同源数据兼容的保证范围。

本地检查使用 CI 同版本 pnpm 10.28.2，安装依赖时禁用脚本。当前主机 Node 26 默认的实验性 Web Storage 会影响 jsdom，测试时使用 `NODE_OPTIONS=--no-experimental-webstorage`。不运行本地 build / dev / Cargo；浏览器生产页面、APK 和设备检查需在已有 CI 或待连接设备上继续。

设备连接后先读取型号、系统、物理 / 覆盖分辨率、DPI、刷新率、输入设备与应用版本；不清除设备数据。对比相同尺寸的连续直线、曲线、拐角、小字、快速回环、不同笔型、不同宽度、手背触点、双指变换、局部擦除及撤销。还原度必须以这张功能清单和同机对照记录计算，不能以新增入口数或代码量代替。
